# #Ongaku エフェクト信号監査 — 2026-09-05

対象はiPhone版の10エフェクト、設定適用、エフェクト後のゲイン／リミッター／フェード。desktopリンク先にある同日の修正を確認し、共通のDynamicsパラメーターIDと秒単位、最終段の−1 dB余裕の方針を合わせた。

## 入出力経路

既存の入力ゲイン・自動DSP → モジュール群 → 推定値に基づく出力トリム → Apple Peak Limiter → −1 dBトリム → フェード用ミキサー → 最終ミキサー。

- [Done] Peak LimiterにはThresholdがないため、従来の文字列検索による−1 dB設定は効いていなかった。数値IDで許容範囲内のAttack 0.001秒／Decay 0.060秒を設定し、リミッター後に−1 dBの段を追加。
- [Done] 前後のトリムで1 dBを二重に差し引かず、診断のoutputTrimDBにも実際の合計トリムを反映。
- [Done] フェードを2個のミキサーへ二重適用していた処理を、専用ミキサー1個に集約。
- [Done] 素早いON/OFF時は保留中の設定を最新のものに置き換え、フェード中の0音量を復帰先として保存しない。キャンセルされたフェードの継続待ちも完了させる。
- [Done] フォーマット再接続後は同一パラメーターでも再適用。省略されたモジュールはOFFにする。

estimatedGainBoostDBは音楽信号に対する参考値で、最大周波数ゲインやピークの上限保証ではない。中間段はFloat PCMであり、以下の1.0超過はエフェクト直後・リミッター前の値。最終出力でサンプルピークを保護する。音色変化に伴う音量差をすべて等ラウドネス化する変更はしていない。

## 各エフェクトの測定

Apple Audio UnitをAVAudioEngineのoffline renderingで実行。アプリの実装ファイル、パラメーター定義、モジュール登録を直接コンパイルし、UI翻訳／ログのみテスト用に置換。

## 確認範囲の限界

- [Next] iPhone実機で実曲を使った音量を合わせた試聴と、再生中の連続ON/OFF・Basic/Pro切り替え。今回の音声測定はmacOS版Apple Audio Unitで、iOSはReleaseビルドによる検証。
- [Later] DAC／Bluetoothなど出力変換後の波形、オーバーサンプリングによるtrue-peak保護、エイリアシング量と知覚音量の定量評価。−1 dBのサンプル余裕は再構成波形の絶対的な上限保証ではない。

Simulation／BBE等は独自EQとApple Audio Unitの組み合わせで、名称に含まれる実機との音響測定上の一致を保証するものではない。
